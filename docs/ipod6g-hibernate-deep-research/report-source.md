# iPod Classic 6G/7G Retained Sleep and Instant Resume

## Playback qualification update — 22 September 2026

P15 was deployed with user authorization. The user reports repeated retained
screen/music-position restoration, but playback is silent and stationary;
Play/Pause twice does not recover it. P16 now saves and restores the CS42L55
register bank lost with its Standby supply, verifies clock/output settings, and
blocks output on restore failure. The clean build, ten host tests and final
ABI-12 linked-image gate pass. P16 is not yet deployed or hardware qualified.

## RetailOS 2.0.4 behavioral audit, Rockbox gap analysis, and production integration

**Date:** 2026-09-05
**Scope:** Rockbox `ipod6g` only (S5L8702; 6th- and 7th-generation iPod Classic)
**Decision:** R12 retained restore and button wake passed on hardware. P12 then proved the exact click-wheel recovery on hardware but froze on its second consecutive cycle. P13 corrected the instruction-proven cross-Standby media lock; its first hardware cycle restored normally, but its second cycle still froze, including a repeat made with no music playing. P14 added the inactive-controller sleep guard and passed its first hardware cycle, but its second consecutive cycle again returned the retained framebuffer frozen. The P14 ELF proves a reachable ATA ownership hazard: it released `ata_mutex` before yielding display/service work, so a database, dircache, pre-wake, or other retained thread could enter ATA before Standby and later continue against a reconstructed controller. No hardware trace proves that a client actually entered that window, so this is the highest-confidence reachable candidate, not a proven cause. The selected dashboard row can change the first storage demand and background-client timing; it cannot change the audited suspend transaction. RetailOS keeps `DiskMgrTask` in state 2 through retained return and UI event 17, then performs state 1 and physical wake only for later demand. P15 models that boundary with a sequence-tagged admission state machine: `OPEN -> OWNED -> WAIT_EVENT -> OPEN`. It carries physical ATA ownership through Standby and base repair, releases the mutex while keeping client demand closed, and reopens demand only after `SYS_HIBERNATE_COMPLETE` has been assigned in the button consumer. A separate instruction trace proves a per-progress RetailOS I2C completion deadline, public error `0x60`, and no retry or controller reset. The P15 source implements that observable contract; its linked/static and physical qualification remain pending.

## Executive verdict

The proven retained core is sound enough to resume on the real device. Rockbox enters PCF50635 Standby with SDRAM retained, the bootloader recognizes a retained record, reconstructs MIU/IRAM/MMU state, and branches directly into the saved application continuation. The linked-image defect that once zeroed live Rockbox BSS is fixed by the ABI-12 private bootloader workspace. R12 subsequently passed retained restore and physical-button wake.

P10 did not enter Standby. Its preserved device-side log proved that the outer session accepted normal playback and had already stopped physical PCM, but the target refused `audio_status=1` as AUDIO. State 5 meant the existing record was PASSED at phase 28 with failure 0. P11 fixed that exact pre-entry contradiction and then reached a different, later boundary on hardware: Standby and retained display restoration completed, but the returned image was unresponsive.

The RetailOS 2.0.4 machine code does prove that P7 modeled audio incorrectly. The action-resource record at `0x08418092` binds long Play/Pause to `HandlePlayPausePressAndHold`. The dispatcher at `0x081c3098` sends ordinary Play/Pause to transport function `0x081c4778`, while long-hold dispatches UI event 15 through `0x0819a628` and `0x0819ab50`. The long-hold branch never calls the transport function. P7's pre-sleep `audio_pause()` and `pcmbuf_pause(true)` therefore contradicted Apple.

RetailOS instead performs a paired physical-output service transition. TPodMediaPlayer vmethod `0x0816f900` posts opcode 8 and waits for completion; `0x0816f9fc` posts opcode 9 and waits for its completion. The worker reaches IRAM functions `0x22007f88` and `0x22007fcc`, which invoke the selected output backend's `+0x10` suspend and `+0x0c` resume methods. The primary backend vtable at `0x089901a0` resolves these slots to `0x081e9904` and `0x081e99bc`. At `0x081e990c` opcode 8 selects object offset `+0x3c`, calls lock wrapper `0x080cc22c` at `0x081e9910`, drains/stops output, and returns at `0x081e99b8` without a matching unlock. Opcode 9 rebuilds output, selects the same `+0x3c` object at `0x081e9a64`, calls unlock wrapper `0x080cc234` at `0x081e9a68`, and returns at `0x081e9a70`. The wrappers branch to the paired lock/unlock implementations at `0x080746ec` and `0x080747c8`. Transport opcodes 0 and 1 are separate worker branches. The required behavior is therefore: preserve transport state, acquire and carry the output-service lock while synchronously stopping physical output, enter retained Standby, rebuild output under that same exclusion, release it once, then return to the retained UI.

The audit also proves that Apple's interrupt transaction saves all 21 EIC topology words: enable, level, and type for each of seven groups. It then programs EIC group 3 bit 3, EIC group 6 bit 28, group 3 low-level/type state, clears VIC0, enables VIC0 mask `0x00080009`, and clears pending EIC groups 3 and 6. Wake clears those pending groups again, restores the saved VIC enable state, and only then restores the 21 EIC words. P8 preserved the saved state but omitted this exact sleep-time topology. Rockbox does not use Apple's VIC vector-address dispatch slots. Neither image's hibernate transaction saves `VICINTSELECT`, and Rockbox's non-vectored dispatcher never reads or configures it.

P13 implements the complete proven media lifetime. `mixer_hibernate_suspend()` takes one PCM lock, sets the physical-start inhibit, stops PCM, and deliberately keeps the lock held while preserving every mixer channel descriptor, callback, playback-thread flag, and transport bit. The target powers down the CS42L55 with MCLK present and gates I2S/DMAC. On wake, `pcm_hibernate_resume()` rebuilds the DMA channel and reapplies the inherited lock before settings or output work. Only after the retained hardware transaction returns does `mixer_hibernate_resume()` recreate physical PCM for an already-active retained channel and perform the sole paired unlock. The linked request handler contains no talk shut-up, `audio_pause()`, `audio_resume()`, fade, `pcmbuf_pause()`, or `pcm_is_playing()` predicate.

P12 masks CPU IRQ/FIQ before the device-manager-equivalent transition, snapshots 16 GPIO groups, performs Apple's mode-2 wheel GPIO sequence, snapshots both VIC enable words and all seven EIC triples, and installs Apple's exact sleep-only EIC/VIC values. On direct continuation it clears pending EIC groups 3 and 6, restores VIC state before EIC state, performs the full wheel mode-3 transaction, restores GPIO, and only then restores UART, PMU, and power. The final linked ARM image is checked for that order.

P10 additionally accounts for a Rockbox-only service absent from the Apple object graph. `notification_manager_hibernate_prepare()` first flushes already-committed notification history, then closes a barrier that rejects new posts and service passes, removes transient banners, stops `PCM_MIXER_CHAN_BEEP`, and invalidates the music baseline without calling `audio_status()` or `audio_current_track()`. It remains invalid through the paired physical-output resume. The barrier consumes the complete notification pass made by the returning `get_action()`, delays periodic polling, and reopens only for the next ordinary UI turn; the first later music poll silently learns the retained state and posts nothing. This mirrors the architectural placement of Apple's broader UI/service quiesce without pretending that Rockbox's custom notification object has an Apple vtable equivalent.

The notification gap was real, but the notification service remains a consumer of playback status, not its owner. P12's second cycle displayed `Playback Stopped`; because the barrier prevents notification work from straddling the transaction, that banner proves playback had already transitioned from Play to Stopped after the failed media lifetime. P13 keeps the barrier unchanged and corrects the exact Apple output-lock mismatch instead of adding notification-side behavior.

P13 hardware testing then separated that observation from the freeze. One retained cycle restored correctly without stopping music, while the second froze. Repeating without music still froze on cycle two. Playback state, the stopped banner, and notification traffic are therefore not required to trigger the defect. P14 then passed cycle one with its inactive-controller sleep guard and reproduced the frozen retained frame on cycle two, proving that the guard removed one invalid access but did not make the complete sleep transaction repeat-safe.

RetailOS serializes disk power through `DiskMgrTask` and the PCF worker queue rather than issuing ATA commands directly from the retained coordinator. The sleep request reaches `0x0805d0b0 -> 0x0803d0d0`, submits type 4 at `0x083883a0`, and changes the worker to state 2 at `0x083883d0`. The worker follows `0x083881cc -> 0x08142d98`, calls the physical sleep vmethod `+0x1c`, and records the inactive result at `0x08388434`. After Standby, the base restore at `0x0805d024` and the state-12 service fanout at `0x0819b2f0..0x0819b360` choose UI event 17 at `0x0819b36c`; no state-1 transition or physical wake routine occurs before that event is queued.

Physical wake remains lazy and client-driven. A later request follows `0x0803d18c -> 0x0803d128(id, 1)`, publishes state 1 at `0x08388498..0x083884a4`, and runs the worker through `0x083884d0 -> 0x083881c0 -> 0x08142ff4`; only then does vmethod `+0x18` reach physical wake at `0x0826e68c`. The primary ATA sleep path routes FLUSH CACHE (`0xe7`) and STANDBY IMMEDIATE (`0xe0`) through a common request guard that rejects an inactive device before register access. P14 matched that command-admission guard, but its separate `storage_sleepnow()` transaction released `ata_mutex` before the retained boundary. Its ELF proves scheduler windows after that release in video-output and LCD work; it does not prove that a particular client occupied the window on the failed run.

P15 retains Apple's lazy physical wake while closing the reachable Rockbox ownership window. `ata_hibernate_suspend_begin(sequence)` changes admission from `OPEN` to `OWNED`, takes `ata_mutex`, and performs synchronous flush/logical idle. `ata_hibernate_resume()` invalidates the reset controller while the same sequence still owns it. After IRQ and tick proof, `ata_hibernate_base_repaired(sequence)` changes `OWNED` to `WAIT_EVENT` and unlocks the physical mutex, allowing callbacks to run without an ATA/filesystem lock inversion while every wake-capable ATA entry still waits. Both the direct request and plugin-READY paths assign their local `ev.id` first; their common `SYS_HIBERNATE_COMPLETE` block then calls `ata_hibernate_event_commit(sequence)`, which changes matching `WAIT_EVENT` to `OPEN`. Every failure path uses `ata_hibernate_abort(sequence)` to reopen demand and release ownership if held. The target override gates the actual 4 KiB read/write wrappers and runtime `ata_init()`, as well as spin, pre-wake, reset, SMART, and other wake-capable entries. The first admitted wake-capable storage demand—not necessarily a sector transfer—performs full physical initialization. For an SSD, the suspend operation is only a proven logical-idle/bookkeeping transition; no untraced rail-off is claimed.

RetailOS places a finite deadline on each PCF/I2C state-machine completion wait. The controller state worker at `0x083608dc` uses write states 10/11/12 and read states 20/21/22/24. Read wrapper `0x08360a78` and write wrapper `0x08360cac` wait for event 61 with literal 100 when interrupts are enabled; in the polling path they call IRAM helper `0x22000428` with `0x186a0`. The deadline is renewed for each state advance rather than spanning the whole multi-byte transaction. Status 5 in the event path and status 31 in the polling path force the failure terminal state, and both wrappers return `0x60` unless the final state is read 24 or write 12. PCF wrappers `0x083624e0` and `0x0836264c` issue no retry and return the transport status. The actual retained caller is `0x0807b270 -> 0x080d8e94 -> 0x082da9b0 -> 0x0836278c -> 0x083624e0`; `0x080d8e94` ignores that status and continues interrupt restoration toward UI event 17. No timeout edge calls the controller initializer or a reset routine. RetailOS nevertheless leaves its `IICUNK10` register-ready polls unbounded, including `0x083608a4`; bounding those polls and using a nonwaiting cleanup in Rockbox are explicit liveness adaptations, not attributed Apple behavior.

## Evidence boundary and method

The Apple reference is the decrypted `osos.fw.decrypted` image for iPod firmware 2.0.4, SHA-256 `f4368251a58b2fdc7b46acf3178dae1d24bc1e029736240741015851256c65c4`, size 10,599,920 bytes [S1]. The audit removes the 0x800-byte container header and applies the real load map: IRAM at `0x22000000`, main DRAM at `0x08000000`, and the final initialization segment at `0x08a0fc88`. The repository audit asserts exact ARM words, branch targets, action-resource bytes, vtable entries, all 35 outer direct calls, and all 21 EIC words. It fails closed if the complete image hash differs.

This is a behavioral interoperability implementation. No Apple firmware bytes are embedded in Rockbox or distributed with the candidate. The NXP PCF50633 manual supports the common OOC/Standby, wake-input, and volatile-memory-rail model [S2]. The public document does not define Apple's PCF50635-specific `OOCSHDWN = 2` convention; that fact comes from the audited Apple instructions and prior real-device retention tests.

Exactness here means matching externally and architecturally relevant behavior. Rockbox cannot and should not copy RetailOS C++ object layouts or unused vectored-interrupt slots. A difference is accepted only when the consumer does not exist in Rockbox and the non-applicability is proven from Rockbox's linked implementation. Unknown stripped Apple calls remain address-labeled; they are not assigned guessed subsystem names.

## Apple's user-visible contract

Apple's iPod classic User Guide specifies holding Play/Pause to turn the player off and pressing any button to turn it on [S5]. The 2.0.4 instruction stream proves that this operation uses retained Standby and a direct continuation. A playing track is not sent a Pause command by long-hold; its physical output service is suspended and resumed around Standby. The long-Play gesture, including its release, belongs to the power transition and is not replayed as a short Play/Pause action after wake. Matching behavior therefore requires the same retained screen and session, no Rockbox logo or database rebuild, a responsive click wheel, continuation of the pre-sleep transport state, and a fresh input epoch that admits new buttons only after the wake gesture is physically neutral.

## Failure reconstruction

1. R6 proved Standby, USB wake, IRAM restoration, and bounded CPU context, but returned through overlapping cold-start memory.
2. R7 directly continued into Rockbox, then released interrupts while the retained I2C mutex was still owned.
3. R8 fixed that order; later breadcrumbs narrowed the stop through LCD and scheduling stages.
4. R10 established Apple's Timer E and polling LCD substrate; R10B restored click-wheel input; R10C proved recurring Timer B ticks.
5. R10D stopped on the first scheduler handoff. Linked addresses then proved that bootloader CRT BSS zeroing overlapped live application globals, including kernel state.
6. R11/ABI 12 moved bootloader BSS into `0x0bf3c000..0x0bffbfff` and retained the direct continuation.
7. R12 added Apple's complete 16-group GPIO snapshot/restore. The user confirmed retained restore and separate physical-button wake on the real iPod.
8. P2, tested while database audio played, cold-booted normal Rockbox because its one-second `pcm_is_playing()` test observed Rockbox's intentional mixer silence tail and refused retained entry.
9. P3-P6 replaced that predicate and expanded refusal/worker coordination. A P6 main-menu wake returned the framebuffer frozen.
10. P7 removed P6's post-wake `audio_resume()` and deliberately paused transport before sleep. The real-device P7 test still returned the framebuffer frozen and the user reported that the track did not pause. P7 therefore disproves the earlier single-cause `audio_resume()` conclusion.
11. The deeper binary trace then proved that P7's deliberate transport pause was itself non-Apple behavior and that the Apple EIC restore covered all seven groups. P8 corrected both facts but was superseded before deployment.
12. A further instruction-by-instruction audit proved that P8 still omitted Apple's sleep-only interrupt topology and placed GPIO restoration before wheel resume. P9 programs the exact sleep VIC/EIC values and matches the observed wheel-before-GPIO wake order.
13. P9 then restored the retained session successfully once on hardware. Its second consecutive attempt returned the retained framebuffer frozen, so P9 failed repeat qualification. The custom notification manager was not part of P9's service barrier and could run storage, overlay, and beep work immediately around the returned request.
14. P10 closed that notification boundary without changing transport or the instruction-proven retained core. Its hardware run did not enter Standby: the preserved log records `session_refusal=0`, `target_refusal=3`, `audio_status=1`, and `pcm_playing=0`. Record state 5 is the prior cycle's PASSED state at phase 28, not a refusal code.
15. The P10 log proves a stale target preflight contradicted both the outer guard and Apple's media contract by rejecting ordinary logical Play after physical output had already stopped. P11 corrected that guard. Its hardware run entered Standby and returned the retained display, but the returned state was frozen.
16. Direct P11/stock disassembly then exposed the first still-proven hardware mismatch at that boundary. P11 stopped and clock-gated the wheel in mode 2, skipped its normal wake path when Hold was locked, ran `s5l_clickwheel_init()`, and dispatched at most one `INT_WHEEL` response. Apple mode 2 only drives E4 low, waits 1 ms, and drives E2 low. Apple mode 3 is unconditional and performs a 25 ms delay, full controller initialization, and a five-zero-response command-state recovery epoch. P12 replaces the approximation and removes P11's recurring post-wake diagnostic instrumentation.
17. P12 hardware cycle 1 restored the retained UI with responsive wheel input, proving the corrected wheel transaction. Cycle 2 returned the retained frame frozen and produced `Playback Stopped`; this was repeat failure with an observed Play-to-Stopped state change, not evidence that the notification service initiated it.
18. Reopening the concrete media backends, rather than only their dispatchers, proved that RetailOS carries one output-object lock from opcode 8 through Standby into opcode 9. P12 balanced separate locks on the two sides. P13 carries the PCM lock across the boundary and uses the target's existing inherited-lock reattachment when the DMA channel is rebuilt.
19. P13 cycle 1 restored correctly, but cycle 2 froze. A separate repeat without music also froze on cycle 2, proving that neither playback nor notification state is a necessary trigger.
20. Rockbox's wake repair deliberately sets `hibernate_storage_reinit_pending` and leaves ATA reinitialization lazy. The earlier sleep path could nevertheless enter `ata_flush_cache()` against a reset controller, and its raw PATA command-block ready waits were unbounded. RetailOS routes both sleep commands through its live-device guard. P14 added the equivalent already-inactive no-op and preserved the pending flag so the next admitted wake-capable demand used full `ata_power_up()`.
21. P14 hardware cycle 1 restored normally. Cycle 2 again returned the retained framebuffer frozen. That result disproved the inactive-command poll as the complete repeat explanation and required auditing every ownership boundary between disk sleep and Standby.
22. The P14 ELF proves `ata_sleepnow()` acquired and released `ata_mutex` internally, then returned to a coordinator that still called yielding video-output/LCD operations before masking CPU interrupts and entering Standby. A database, dircache, pre-wake, or other retained thread could therefore acquire ATA, begin power-up or transfer, and be suspended inside that transaction. Resume would then reconstruct ATA/DMAC before that client continued. This is the highest-confidence reachable explanation for a visible restored framebuffer followed by a storage/filesystem stall, but no cycle-2 trace proves that the path was taken. The selected-row preview runs synchronously in the suspending main/button-consumer thread and cannot itself be frozen mid-call; selection can change pre/post-wake I/O and the population and timing of later clients.
23. The deeper RetailOS trace proves that Apple completes disk sleep in manager state 2, restores the base, and queues UI event 17 without state 1, then performs state 1 and physical wake only for later client demand. P15 uses matching-sequence `OPEN -> OWNED -> WAIT_EVENT -> OPEN` admission. Suspend and controller invalidation run in `OWNED`; IRQ/tick proof moves to `WAIT_EVENT` and releases `ata_mutex`; both button-consumer success paths assign `ev.id` before the common event commit moves to `OPEN`. Abort reopens every failure path. This avoids holding ATA across callbacks without admitting storage before event assignment.
24. P15 gates all actual 4 KiB read/write wrappers, runtime `ata_init()`, and other wake-capable ATA entries. It bounds PATA command-block polls, propagates full-initialization failure, and leaves the SSD retryable: pending state clears only after complete `ata_power_up()` success. SSD suspend is documented as logical idle; neither the stock trace nor P15 proves a physical SSD rail-off. Pre-wake is an optimization and does not define success.
25. The retained input return models the complete long gesture rather than only queue cleanup. Only an exact unmodified long Play can commit poweroff; its release is consumed while short Play remains ordinary. Hold reconciliation is a Rockbox adaptation because RetailOS has a proprietary transitional power-state gate. The post-mode3 `0x8000023a` neutral query is also a Rockbox adaptation: Apple mode 3 does not issue it, although its mode-0 implementation proves the protocol. A syntactically valid all-buttons-up sample opens the gate; timeout/malformed data does not, and later real controller packets can establish neutrality.
26. A further primary trace proves bounded normal PCF/I2C state completion before event 17. Retail uses a 100-unit event wait or `0x186a0` polling deadline per state advance and returns `0x60` with no retry when the read/write terminal state is not reached. The retained interrupt-restore caller ignores that status and continues. Source audit confirms that P15 starts a fresh 100-ms `i2c_wait_io()` budget for each START/data/STOP progress step, normalizes every public failure to `0x60`, and contains no retry or controller reinitialization. Bounding raw controller-ready polls and using nonwaiting timeout cleanup are explicit Rockbox liveness adaptations; linked and hardware qualification remain pending.

The latest completed hardware boundary is P14: cycle 1 passed and cycle 2 froze on the retained frame. P15 is the current source candidate and has no recorded physical result in this report. Its final build, clean rebuild comparison, linked-image/static gates, hashes, packaging, and deployment status remain pending until the corresponding results are supplied.

## P15 implementation contract

The request handler accepts only stopped, ordinary playing, or playing+paused audio and refuses unsupported plugin/recording ownership. The target repeats exactly that policy from one coherent `audio_status()` snapshot after physical output is stopped. Neither guard accepts pause-only, recording, or unknown ownership bits. The request does not silence talk or alter transport. Before the media transition, it flushes and suspends the custom notification service, clears transient presentation state, stops the notification beep channel, and invalidates its music baseline without touching playback. `mixer_hibernate_suspend()` then takes the PCM lock, sets a physical-start inhibit, stops PCM, and keeps that lock held across Standby. Active mixer-channel objects remain in retained DRAM.

The target coordinator starts with `ata_hibernate_suspend_begin()`. It takes `ata_mutex`, performs the synchronous flush/logical-idle operation through the locked helper, and retains that single ownership level across all later video-output, PCM, UART, LCD, backlight, and setup calls that may yield, as well as across Standby itself. No other Rockbox database, dircache, preview, pre-wake, or filesystem client can enter ATA during that interval. If begin fails, it marks the controller invalid and reinitialization/I/O pending, clears the ownership marker, and unlocks before returning the error. A successful begin never wakes an already-inactive SSD and does not force an unproven SSD rail-off cycle. The coordinator then disables composite output through its normal service path, powers down codec output, gates I2S, and suspends UART/display/backlight. It acquires I2C ownership and masks CPU IRQ/FIQ before snapshotting 16 GPIO groups, suspending the wheel, and saving both VIC enable words plus all seven EIC triples. It installs Apple's exact sleep-only EIC/VIC values, clears pending groups 3/6, saves context, and enters Standby.

On direct continuation, the retained path restores Timer E, clocks, VIC/DMAC hardware and storage; `ata_hibernate_resume()` marks the reconstructed controller invalid and leaves lazy initialization pending while the matching sequence remains `OWNED`. The path then clears pending EIC groups 3/6; restores saved VIC state followed by all seven EIC triples; executes Apple's unconditional 25 ms wheel reinitialization and bounded command-state transaction; restores GPIO; and restores UART, PMU, power, USB, target PCM registers, and LCD/framebuffer while CPU IRQ/FIQ remain controlled. When DMAC is reconstructed, `pcm_hibernate_resume()` reapplies the carried PCM lock to the new playback channel before applying settings. After the saved VIC topology is live, the coordinator restores CPU interrupts, proves a fresh Timer B tick, and calls `ata_hibernate_base_repaired(sequence)`. That transition changes `OWNED` to `WAIT_EVENT` and releases the mutex before PMU, LCD, or video-output callbacks, but does not admit ATA demand or wake storage. Every failure calls `ata_hibernate_abort(sequence)`, which returns admission to `OPEN` and releases ownership if necessary.

The direct and plugin-READY button-consumer paths both assign `ev.id` before entering one common `SYS_HIBERNATE_COMPLETE` block. Only there does `ata_hibernate_event_commit(sequence)` change matching `WAIT_EVENT` to `OPEN`. The target's actual 4 KiB read/write wrappers and runtime `ata_init()` use the same admission lock, as do the other wake-capable ATA paths, so no storage client can reopen the controller before this queue-assignment boundary. The first admitted wake-capable demand then performs full initialization; it need not be a sector transfer. Every PATA command-block-ready handshake is bounded, initialization failure propagates without clearing retry state, and SSD suspend remains a logical-idle operation with no claimed rail cycle. This matches Apple's state-2-through-event-17 and later demand-driven state-1 ordering without holding ATA across callbacks.

Only an exact, unmodified long Play repeat can commit the retained power gesture. The committed release is consumed exactly once and short Play remains ordinary input. Wheel resume resets target command state, core debounce/repeat state, the action mapper, and stale non-system queue state. Rockbox's Hold reconciliation and post-mode3 `0x8000023a` sample are adaptations, not literal Retail mode-3 calls: the query may open the wake gate only on a syntactically valid all-buttons-up reply, while timeout/malformed data keeps it closed until a later real neutral packet. The `0x8000063a` command-state recovery also bounds malformed nonzero replies because Rockbox's asynchronous ISR can race the synchronous exchange. The successful request assigns `SYS_HIBERNATE_COMPLETE`, Rockbox's equivalent of event 17, before committing storage admission. The dashboard preserves the selected row and redraws without interpreting wake as a menu action; selection can affect the first later storage demand, not suspend entry.

Only after the low-level transaction has returned with normal execution available does `mixer_hibernate_resume()` clear the inhibit, restart PCM for an already-active retained channel, and perform the sole paired unlock. PMU completion, token cleanup, and an active-channel codec restart can all enter normal I2C after the framebuffer is restored and before the event ID is assigned. P15 therefore gives normal START/data/STOP/off progress a finite bound, returns `0x60`, and performs no retry or reinitialization. This mirrors the proven Retail transport outcome; bounding raw ready polls and nonwaiting cleanup are Rockbox liveness adaptations. The notification baseline stays invalid, the returning action's notification pass is discarded, and the service reopens only on a later UI turn. Production builds contain no recurring tick, scheduler-switch, PMU-ADC, or runtime-checkpoint diagnostic hook.

The final linked P15 gate is required to enforce that order, including notification close before mixer suspend and notification reopen after timer/button cleanup. It requires suspend to lock then stop with no unlock; resume to restart then unlock exactly once with no fresh lock; target reattachment of the inherited PCM lock after DMA reconstruction; and rejection of transport/fade/talk calls, duplicate target `pcm_play_stop()`, and premature target DMA starts. Its ATA checks require matching-sequence `OPEN -> OWNED -> WAIT_EVENT -> OPEN`, all real 4 KiB wrappers and runtime `ata_init()` behind admission, cleanup on every failure, base repair before callbacks, event commit only after `ev.id` assignment in both success paths, no eager wake, bounded PATA polls, and lazy-init error propagation. Its input checks distinguish literal long-Play/release behavior from Rockbox Hold, `0x23a`, and malformed-reply adaptations. Its I2C checks require bounded normal progress, `0x60` timeout, and no retry/reinit claim. The gate retains notification, GPIO, EIC/VIC, PMU, ABI-12, wheel, and diagnostic-absence checks and requires the distinct dark P15 identity. Final P15 execution remains pending.

## Bottom line

P13 proved that the media lock can complete one playing cycle and then reproduced the cycle-2 freeze even with no music, ruling out playback and notifications as necessary causes. P14 added Apple's inactive-device command guard and passed once, but froze on its second cycle. Its ELF exposes a concrete reachable contradiction: it released `ata_mutex` after logical disk idle while the coordinator still had yielding work before Standby, allowing a client to enter before controller reconstruction. Because no failed-cycle trace identifies such a client, this remains the highest-confidence reachable candidate rather than a proven cause. Dashboard selection can change later demand and timing; it is not a distinct hibernate branch.

RetailOS completes disk sleep in state 2, remains there through base restoration and UI event 17, and enters state 1 plus physical wake only for later demand. P15 models this with sequence-tagged `OPEN -> OWNED -> WAIT_EVENT -> OPEN`: physical mutex ownership spans sleep, yields, Standby, controller invalidation, IRQ restoration, and tick proof; admission stays closed after the mutex is released and opens only after the resume event ID is assigned. All real 4 KiB wrappers and runtime initialization are gated, and the first admitted wake-capable demand receives bounded, retry-safe initialization results. SSD idle is logical, while Hold reconciliation and the post-mode3 `0x23a` neutral sample are explicit Rockbox adaptations. Source audit confirms the additional per-progress, no-retry normal-I2C boundary with public `0x60` failure before event 17; final linked/static qualification, artifact identities, deployment, and repeated P15 hardware testing remain pending.
